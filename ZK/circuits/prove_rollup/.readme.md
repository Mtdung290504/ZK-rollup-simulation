# ZK-Rollup Circuit Specification

> **Version:** 1.0  
> **Language:** Circom 2.1.0  
> **Dependencies:** circomlib (Poseidon, EdDSAPoseidon, Bitify, Comparators, Mux1, Gates)  
> **Deployed config:** `BatchRollup(N_TXS=4, DEPTH=4)`

---

## Circuit Hierarchy

```
BatchRollup (index.circom)
│
├── ProcessTx × N_TXS          (process_tx.circom)
│   ├── VerifyTxSignature       (verify_tx.circom)
│   ├── MerkleTreeUpdater × 2  (merkle_updater.circom)  — sender & receiver
│   └── AccountLeaf × 4        (account_leaf.circom)    — 2 old + 2 new states
│
├── MerkleTreeUpdater × 1      (merkle_updater.circom)  — operator fee collection
├── AccountLeaf × 2            (account_leaf.circom)    — operator old & new
└── BinaryHashTree             (da_hash.circom)         — DA commitment
```

## System Parameters

| Parameter | Value | Meaning |
|---|---|---|
| `N_TXS` | 4 | Max transactions per batch (including padding) |
| `DEPTH` | 4 | Sparse Merkle Tree depth → max 2⁴ = 16 accounts |
| Field modulus `p` | ~2^253.6 | BN254 field; all signals are in `[0, p-1]` |

**Bit-width conventions:**

| Data type | Width | Reason |
|---|---|---|
| `balance`, `amount`, `fee` | 128-bit | Sufficient for any currency denomination |
| `nonce` | 64-bit | Sufficient for any account lifetime |
| `total_deduct = amount + fee` | 128-bit max | Sum of two 128-bit values |
| Accumulated fees, operator balance | 128-bit | Checked after accumulation |

## Sub-circuits

### AccountLeaf (`account_leaf.circom`)
Hashes an account state into a single leaf value:
```
leaf = Poseidon(pubKey_x, pubKey_y, balance, nonce)
```
`EMPTY_LEAF = Poseidon(0,0,0,0)` — represents an unoccupied slot. A valid BabyJubJub public key is never `(0,0)`, so no real account can collide with this value.

Range checks on `balance` and `nonce` are the caller's responsibility (done in `ProcessTx`).

---

### VerifyTxSignature (`verify_tx.circom`)
Validates sender signature and computes the transaction hash for the DA tree.

Internal flow:
1. `to_addr = Poseidon(to_x, to_y)`
2. `msg_hash = Poseidon(to_addr, amount, fee, nonce)` — this is what the user signs
3. `EdDSAPoseidonVerifier(enabled, from_x, from_y, msg_hash, R8x, R8y, S)`

When `enabled = 0` (padding), the verifier is disabled — no valid signature is required. `msg_hash` is still computed for DA commitment purposes (hash of zeroed data is safe).

The `nonce` inside `msg_hash` makes signatures non-replayable across different nonce values.

---

### BinaryHashTree (`da_hash.circom`)
Builds a binary Merkle tree over all transaction hashes in the batch:
```
Input:  tx_hashes[N_TXS]
Output: tree_root  (DA commitment)
```
`N_TXS` must be a power of 2. With N_TXS=4, the tree has 7 nodes (2×4−1).

---

### MerkleTreeUpdater (`merkle_updater.circom`)
Updates a Sparse Merkle Tree leaf and computes the new root, given a Merkle path.

For each leaf update:
1. Verify the old leaf is consistent with the current root (path verification)
2. Hash the new leaf value
3. Recompute the root along the same path

**Path-address binding:** The Merkle path bits are derived from the account index, which is committed to the account leaf hash. An account cannot claim a path belonging to a different index.

---

### ProcessTx (`process_tx.circom`)
Orchestrates one transaction: verify signature → update sender leaf → update receiver leaf → collect operator fee.

**Transaction types:**

| Type | Description | Signature |
|---|---|---|
| `0` | Transfer (L2 → L2) | Signed by sender (9 fields) |
| `1` | Deposit (Treasury → User) | Signed by Treasury sequencer |
| `2` | Withdrawal (User → Treasury) | Signed by sender with L1 address |

**Enforced constraints per transaction:**
- Sender balance ≥ amount + fee (checked as 128-bit values to prevent overflow)
- Nonce matches exactly (prevents replay)
- Self-transfer is blocked: `from_x ≠ to_x OR from_y ≠ to_y`
- For deposits (type 1): `from_x` and `from_y` must equal the hardcoded Treasury public key

---

### BatchRollup (`index.circom`)
Top-level circuit. Processes all N_TXS transactions and produces public outputs.

**Public input:**
- `publicInputHash` — a single Poseidon hash of all public values

**Public values (hashed together):**
- `oldStateRoot` — Merkle root before the batch
- `newStateRoot` — Merkle root after all transactions
- `daTreeRoot` — DA commitment (binary hash of all tx hashes)
- `operationsHash` — chained hash of all deposit operations: `Poseidon(prev, deposit_id, to_x, to_y, amount)`

**Deposit integrity:** The `operationsHash` chains all deposit transactions in order. L1 independently computes the same hash from its `pending_deposits` queue and checks it matches the circuit output. This prevents the Sequencer from minting, reordering, or omitting deposits.

**Padding:** Transactions with `enabled=0` are no-ops — state does not change, signatures are not checked, and the contribution to `operationsHash` is zero.

## Data Flow Summary

```
input.json
  │
  ├── ProcessTx[0..N-1]
  │     ├── VerifyTxSignature → msg_hash[i]
  │     ├── MerkleTreeUpdater (sender)
  │     └── MerkleTreeUpdater (receiver)
  │
  ├── MerkleTreeUpdater (operator, accumulates fees)
  │
  ├── BinaryHashTree(msg_hash[]) → daTreeRoot
  │
  └── Poseidon(oldRoot, newRoot, daRoot, opsHash) → publicInputHash
```

## Security Properties Summary

| Property | Mechanism |
|---|---|
| No minting | Treasury public key hardcoded in circuit; balance conservation enforced |
| No replay | Nonce in message hash; signature covers nonce |
| No double-deposit | `operationsHash` chains deposit_id in order; L1 verifies against its queue |
| No path forgery | Path bits derived from account index committed in leaf hash |
| No self-transfer | Explicit constraint: sender ≠ receiver |
| Withdrawal binding | L1 checks `msg.sender == l1_address` from DA proof |
| DA completeness | Every transaction's hash committed into `daTreeRoot` |
